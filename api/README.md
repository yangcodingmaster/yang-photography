# 留言表单 —— 安装说明

给你自己看的操作手册。全程在宝塔面板里点，大约 10 分钟。

怎么工作：访客点「Leave a message 留言」→ 填表单 → 点寄出 → **内容直接发到你邮箱**。
服务器上不存任何东西，网站上也不显示别人的留言。

---

## 零、先搞清楚东西放在哪

| 东西 | 位置 | 会不会进 git / 被部署覆盖 |
|---|---|---|
| `message.php`（代码） | `/www/wwwroot/yangzhaophoto.com/api/` | 进 git，每次部署覆盖（正是想要的） |
| `message.js`（前端） | 网站根目录 | 进 git，每次部署覆盖 |
| `config.php`（**API key**） | `/www/site-secrets/` | ❌ 不进 git，不被部署碰 |

> **为什么 key 要单独放在网站目录外面？**
>
> 两个原因。一是那个位置公网访问不到，别人扒不走。二是 `scripts/deploy.sh` 用的是
> `rsync --delete`，它让服务器变成本地的镜子 —— 服务器上有、本地没有的文件一律删掉。
> key 恰好就是"只在服务器上存在"的东西，放网站目录里的话，你下次更新几张照片跑一次
> 部署，它会被静悄悄地删掉，然后留言功能就无声无息地坏了。

> **为什么不能干脆不要 PHP，让网页直接调 Resend？**
>
> 因为 key 一旦写进前端 JS，任何人按一下"查看网页源代码"就能拿到，
> 然后用你的域名发垃圾邮件，最后是你的域名被拉黑。
> key 必须待在服务器上，访客的浏览器永远碰不到它。

---

## 一、确认这个站点能跑 PHP

宝塔 → **网站** → 找到 `yangzhaophoto.com` → 点 **设置** → 看 **PHP 版本** 那一栏。

- 如果显示「纯静态」→ 改成 **PHP-80**（或列表里有的任意 8.x / 7.4）。
  纯静态的话，`.php` 文件会被当成文本原样吐给浏览器，等于源码全公开。
- 没有任何 PHP 版本可选 → 宝塔 → **软件商店** → 搜 `PHP` → 装一个 8.0，再回来选。

## 二、⚠️ 关掉「防跨站攻击」（这一步不做，后面一定失败）

还是在这个站点的 **设置** 里，找到 **网站目录** 这一页，有一个
**防跨站攻击 (open_basedir)** 的开关 —— **把它关掉**。

它的作用是把 PHP 能读的范围锁死在网站目录里。而 key 故意放在网站目录*外面*
（第零节解释了原因），开着它 PHP 就永远读不到，体检会报"配置文件找不到"。

## 三、拿 Resend 的 API key

1. 登录 [resend.com](https://resend.com) → **API Keys** → **Create API Key**
   → 权限选 `Sending access` → 复制那串 `re_xxxxxxxx`（**只显示这一次**）
2. 发件域名二选一：
   - **先跑通流程**：`MAIL_FROM` 填 `onboarding@resend.dev`。
     限制是只能发到你注册 Resend 用的那个邮箱，但测试足够了。
   - **正式用**：Resend → **Domains** → 添加 `yangzhaophoto.com` → 按它给的
     几条 DNS 记录去域名商后台加上 → 等验证变绿 → 然后
     `MAIL_FROM` 填 `Yang Photography <noreply@yangzhaophoto.com>`

## 四、生成体检口令

宝塔 → **终端**，粘贴这一行回车：

```bash
openssl rand -hex 24
```

会吐出一串 48 位的字符，复制下来。它只用在第七步的体检页面上，防止别人随便
探你的配置状态。

## 五、写配置文件

宝塔 → **文件** → 进到 `/www/` → **新建目录**，名字 `site-secrets`。
进去 → **新建文件**，名字 `config.php`。双击打开，把项目里
`api/config.sample.php` 的内容整个粘进去，填上四个值：

```php
'RESEND_API_KEY' => 're_你刚复制的那串',
'ADMIN_EMAIL'    => 'zcqshck@ucl.ac.uk',
'MAIL_FROM'      => 'onboarding@resend.dev',
'ADMIN_TOKEN'    => '第四步生成的那串',
```

保存。**这个文件永远不要复制回项目文件夹**，那样等于把 key 推上 GitHub。

> 权限不用改。这个文件 PHP 只读不写，默认权限就够。

## 六、部署

本地项目目录里跑：

```bash
bash scripts/deploy.sh --dry-run
```

看一眼清单里有 `api/message.php` 和 `message.js`，没问题再跑正式的：

```bash
bash scripts/deploy.sh
```

## 七、体检

浏览器打开（把 `你的口令` 换成第四步那串）：

```
https://yangzhaophoto.com/api/message.php?action=selftest&token=你的口令
```

八项全绿就没问题。常见的红：

| 报错 | 原因 | 怎么修 |
|---|---|---|
| 页面显示的是 PHP 源代码 | 站点是「纯静态」 | 回第一步选 PHP 版本 |
| 配置文件 ❌ 找不到 | 防跨站攻击没关，或路径写错 | 回第二步 / 检查第五步的路径 |
| curl 扩展 ❌ | PHP 没装 curl | 宝塔 → 软件商店 → PHP → 设置 → 安装扩展 → curl |
| Resend API Key ❌ 空的 | config.php 里没填 | 回第五步 |

## 八、走一遍真实流程

1. 打开 `https://yangzhaophoto.com/gallery.html`，滚到底，点 **Leave a message 留言**
2. 随便写一句，点 **Send 寄出** → 应该显示"寄出了，谢谢你写这些。"
3. 查邮箱 → 应该收到一封带留言内容的邮件

第 3 步没收到：先看垃圾箱；还没有就去 Resend 后台 **Logs** 看具体原因
（多半是 `MAIL_FROM` 的域名没验证）。

> 注意：**这个表单不存任何东西**，发不出去就是彻底丢了。所以代码里发送失败时会
> 明确告诉访客"没能寄出"，不会假装成功 —— 免得别人以为写到了、你却什么都没收到。

## 日常使用

没有后台，没有要维护的东西。有人留言你就收到一封邮件。

- 对方**留了邮箱**：邮件的回信地址（reply-to）已经设成他的地址，
  你在邮箱里直接点「回复」就是回给他，不用手动复制粘贴
- 对方**没留邮箱**：邮件里会写明"对方没有留邮箱，回不了"

## 内置的防护

| 手段 | 挡什么 |
|---|---|
| 蜜罐字段 | 页面上有个藏起来的输入框，真人看不见；填了的直接丢弃 |
| 同 IP 60 秒冷却 | 挡住刷屏 |
| 正文限 2000 字 / 名字限 40 字 | 挡住贴一整篇小说 |
| 邮件内容全部转义后再拼 | 别人写的 HTML 只会当文字显示，不会在你的邮件客户端里生效 |
| API key 只在服务器上 | 前端拿不到，扒不走 |

垃圾留言直接进你邮箱是这个方案的代价（不像留言板可以先审后发）。
真被机器人盯上了，最简单的办法是在邮箱里加一条过滤规则。

## 想在本地先试试（可选）

本地测试需要机器上有 PHP。macOS 13 现在没有现成的安装包（Homebrew 只能从源码
编译整条依赖链，要一两个小时），所以**不装也完全没问题** —— 直接部署到服务器上，
用第七步的体检和第八步的实测来验证，效果一样。

真要在本地跑的话，装好 PHP 之后：

```bash
MESSAGE_CONFIG=/tmp/gb-test/config.php php -S localhost:8899 -t .
```

`MESSAGE_CONFIG` 这个环境变量会临时把配置文件指到别处，服务器上不设它，
走的还是 `/www/site-secrets/config.php`。
